## 四、实验内容

设计并实现智能车控制系统的执行器 `Executor` 组件，支持基本控制指令（对应需求文档《需求1-基本控制指令》）：

- `Executor` 提供初始化接口，负责初始化车辆位置和朝向，输入为 `(x, y, heading)`，其中 `x`、`y` 为 `int32` 坐标，`heading` 为 `N/S/E/W` 朝向；默认初始化位置为 `(0, 0, N)`。
- `Executor` 支持执行移动与转向指令：`M` 前进 1 格、`L` 左转 90 度、`R` 右转 90 度，并支持批量指令执行。
- `Executor` 提供查询接口，返回车辆当前坐标和朝向。

要求：设计对外接口并实现上述功能；设计并构建单元测试用例。约束：坐标值在 `int32` 范围内、无需考虑溢出；传入参数均合法。

## 六、实验步骤及操作

**1. 搭建工程目录结构**

采用 `include`（对外接口）、`src`（实现）、`tests`（测试）三层结构：

```
├── src/Executor.cpp          # 工厂方法与 Pose 比较
└── tests/ExecutorTest.cpp    # 单元测试
```

**2. 定义对外接口**

在 `include/Executor.hpp` 中定义位置类型 `Pose` 和抽象接口 `Executor`，使用工厂方法 `NewExecutor` 创建对象：

```cpp
namespace adas {
struct Pose { int x; int y; char heading; };

class Executor {
public:
    static Executor* NewExecutor(const Pose& pose = {0, 0, 'N'}) noexcept;
    virtual ~Executor() = default;
    Executor(const Executor&) = delete;
    Executor& operator=(const Executor&) = delete;
    virtual void Execute(const std::string& commands) noexcept = 0;
    virtual Pose Query() const noexcept = 0;
};
}
```

**3. 实现 ExecutorImpl**

在 `src/ExecutorImpl.cpp` 中把面向过程的 `if/else` 拆分为三个职责单一的辅助函数，并在 `Execute` 中按字符分发：

```cpp
char TurnLeft(char heading) noexcept { /* N->W->S->E->N */ }
char TurnRight(char heading) noexcept { /* N->E->S->W->N */ }
void MoveForward(Pose& pose) noexcept {
    switch (pose.heading) {
        case 'N': ++pose.y; break;
        case 'S': --pose.y; break;
        case 'E': ++pose.x; break;
        case 'W': --pose.x; break;
        default: break;
    }
}

void ExecutorImpl::Execute(const std::string& commands) noexcept {
    for (const char command : commands) {
        switch (command) {
            case 'M': MoveForward(pose_); break;
            case 'L': pose_.heading = TurnLeft(pose_.heading); break;
            case 'R': pose_.heading = TurnRight(pose_.heading); break;
            default: break;
        }
    }
}
```

**4. 编写单元测试**

编写覆盖默认状态、初始状态、四方向移动、转向、组合指令、空指令共 6 个用例的测试程序，测试函数命名遵循"行为 + 前提 + 预期"的规范。

## 十、总结及心得体会

1. 通过本实验，理解了"对外接口稳定、实现细节可替换"的设计思想：`Executor` 抽象类只暴露 `Execute` 和 `Query`，实现类 `ExecutorImpl` 可以自由演化而不影响调用方。
2. 体会到将复杂逻辑拆分为 `TurnLeft`、`TurnRight`、`MoveForward` 等单一职责函数，能显著降低圈复杂度、提升可读性和可测试性。
3. 初步掌握了测试驱动开发的节奏：先为每个行为写出"应当如何"的测试，再以最少代码让测试通过，使实现始终有测试兜底。
4. 学会了用 `std::tie` 简化结构体相等比较、用 `new (std::nothrow)` 避免工厂方法抛异常等细节。

## 十一、对本实验过程及方法、手段的改进建议

1. 当前 `Execute` 中仍以 `switch` 逐字符分发，当指令增多时代码会变长，后续可考虑引入"指令表 + 回调"的表驱动方式。
2. 朝向流转目前用四个方向的 `switch` 硬编码，可抽象为方向枚举并利用取模运算，使左转/右转更简洁。
3. 测试用例对非法指令与极端坐标（`int32` 边界）的覆盖有限，可补充异常/边界场景的测试以增强健壮性。
