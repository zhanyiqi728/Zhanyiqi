## 三、实验目的

1. 掌握通过"数据抽离"解耦类之间循环依赖的方法。
2. 掌握表驱动（`std::unordered_map` 映射指令对象）以消减 `if/else` 分支、降低圈复杂度。
3. 掌握将状态流转抽象为数值运算的方法（`Direction` 数值化编码）。
4. 在实验二基础上新增倒车指令 `B`，理解 `F` 与 `B` 两种状态的正交叠加语义。

## 四、实验内容

在实验二 `Executor` 基础上，新增倒车指令 `B`，并通过数据抽离、表驱动和状态抽象优化面向对象结构（对应需求文档《需求3-支持倒车功能》）：

- 基础指令：`M` 前进 1 格、`L` 左转 90 度、`R` 右转 90 度。
- 加速指令 `F`：切换加速状态，加速态下 `M` 前进 2 格、`L/R` 先前进 1 格再转。
- 倒车指令 `B`：切换倒车状态，倒车态下 `M` 后退 1 格、`L/R` 变成反方向转向（位置不变）。
- `B` 与 `F` 可叠加：叠加态下 `M` 后退 2 格、`L/R` 先后退 1 格再反方向转向。

## 六、实验步骤及操作

**1. 数据抽离解耦循环依赖**

把 `ExecutorImpl` 中的状态数据（位置、朝向、加速/倒车标志）抽离到 `PoseHandler`，使指令类只依赖 `PoseHandler` 而非 `ExecutorImpl`，消除循环依赖：

```cpp
class PoseHandler final {
    Point point;              // 位置
    const Direction* facing;  // 朝向
    bool fast{false};         // 加速状态
    bool reverse{false};      // 倒车状态
public:
    void Forward(); void Backward();
    void TurnLeft(); void TurnRight();
    void Fast(); void Reverse();
    bool IsFast() const; bool IsReverse() const;
    Pose Query() const;
};
```

**2. 状态抽象**

`Point` 封装位置变化向量，`Direction` 用 `E/S/W/N` 的数值编码，左转 `(index+3)%4`、右转 `(index+1)%4`，把复杂状态流转简化为算术运算：

```cpp
const Direction directions[4] = { {0,'E'}, {1,'S'}, {2,'W'}, {3,'N'} };
const Direction& Direction::LeftOne() const noexcept  { return directions[(index + 3) % 4]; }
const Direction& Direction::RightOne() const noexcept { return directions[(index + 1) % 4]; }
const Point& Direction::Move() const noexcept { /* E/S/W/N 对应 (1,0)/(0,-1)/(-1,0)/(0,1) */ }
```

**3. 指令抽象与倒车语义**

`Command.hpp` 中定义 `ICommand` 及各指令类；`MoveCommand` 依据 `fast/reverse` 状态决定前进/后退与步数：

```cpp
class MoveCommand final : public ICommand {
    void DoOperate(PoseHandler& h) const noexcept override {
        if (h.IsFast())   { h.IsReverse() ? h.Backward() : h.Forward(); }
        if (h.IsReverse()) h.Backward(); else h.Forward();
    }
};
```

倒车状态下的左转/右转语义互换（`L`→右转、`R`→左转），由 `TurnLeftCommand`/`TurnRightCommand` 内的 `IsReverse` 判断实现。

**4. 表驱动消减圈复杂度**

`ExecutorImpl::Execute` 用 `std::unordered_map<char, std::unique_ptr<ICommand>>` 以字符为键映射指令对象，消除 `if/else` 分支：

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept {
    std::unordered_map<char, std::unique_ptr<ICommand>> cmderMap;
    cmderMap.emplace('M', std::make_unique<MoveCommand>());
    cmderMap.emplace('L', std::make_unique<TurnLeftCommand>());
    cmderMap.emplace('R', std::make_unique<TurnRightCommand>());
    cmderMap.emplace('F', std::make_unique<FastCommand>());
    cmderMap.emplace('B', std::make_unique<ReverseCommand>());
    for (const char cmd : commands) {
        const auto it = cmderMap.find(cmd);
        if (it != cmderMap.end()) it->second->DoOperate(poseHandler);
    }
}
```

## 十、总结及心得体会

1. 数据抽离把"状态"集中到 `PoseHandler`，使指令类与 `ExecutorImpl` 解耦，依赖方向更清晰，是消除循环依赖的有效手段。
2. 表驱动让指令分发从"新增分支"变为"新增表项"，`Execute` 的圈复杂度大幅下降，新增指令的改动面更小。
3. 将朝向抽象为数值索引并用取模运算实现左右转，把原本多个 `switch` 的重复逻辑压缩为一行，代码更简洁、更不易出错。
4. 体会到 `F` 与 `B` 作为两个正交的标志位可以自然组合，无需为叠加态单独编码，体现了状态正交化设计的价值。

## 十一、对本实验过程及方法、手段的改进建议

1. 各指令类中的 `fast`/`reverse` 判断存在重复代码，可进一步抽象出"步进动作"与"转向动作"的选择逻辑，减少重复。
2. 当前指令表在每次 `Execute` 调用时重新构建，若指令频繁执行可将其提升为成员或静态对象以复用。
3. 可引入动作序列（Action List）思想，让指令先返回动作列表再统一执行，为更复杂的指令编排（如掉头）做准备。
