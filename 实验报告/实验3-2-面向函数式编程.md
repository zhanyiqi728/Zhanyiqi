## 二、实验项目名称

面向函数式编程 —— 用函数对象替代继承多态实现 Executor 指令

## 三、实验目的

1. 理解函数式编程的核心思想：以函数对象（`operator()` 重载）替代继承多态。
2. 掌握 `std::function` 的用法，以及用 `std::unordered_map<char, std::function<...>>` 做表驱动。
3. 理解 `std::function` 的生命周期与拷贝语义，避免悬空引用问题。
4. 在实验三（一）基础上，用函数式方式实现同样的 ADAS 指令语义，验证两种范式的等价性。

## 四、实验内容

在实验三（一）基础上，用函数式编程替代继承多态，实现同样的指令语义：

- 基础指令：`M` 前进 1 格、`L` 左转 90 度、`R` 右转 90 度。
- 加速指令 `F`：切换加速状态，加速态下 `M` 前进 2 格、`L/R` 先前进 1 格再转。
- 倒车指令 `B`：切换倒车状态，倒车态下 `M` 后退 1 格、`L/R` 变成反方向转向。
- `B` 与 `F` 正交叠加：叠加态下 `M` 后退 2 格、`L/R` 先后退 1 格再反方向转向。

状态抽象（`Point` / `Direction` 数值编码）与实验三（一）保持一致。

## 六、实验步骤及操作

**1. 移除 `ICommand` 继承体系**

指令不再是继承体系中的子类，而是各自独立的函数对象（重载 `operator()`）：

```cpp
class MoveCommand final {
public:
    void operator()(PoseHandler& h) const noexcept {
        if (h.IsFast())   { h.IsReverse() ? h.Backward() : h.Forward(); }
        if (h.IsReverse()) h.Backward(); else h.Forward();
    }
};
```

**2. `std::function` 表驱动**

`Execute` 用 `std::unordered_map<char, std::function<void(PoseHandler&)>>` 以初始值列表一次构建完成，指令对象被隐式转换为 `std::function`：

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept {
    const std::unordered_map<char, std::function<void(PoseHandler&)>> cmderMap {
        {'M', MoveCommand()}, {'L', TurnLeftCommand()}, {'R', TurnRightCommand()},
        {'F', FastCommand()}, {'B', ReverseCommand()},
    };
    for (const char cmd : commands) {
        const auto it = cmderMap.find(cmd);
        if (it != cmderMap.end()) it->second(poseHandler);
    }
}
```

**3. 生命周期安全**

表里存的是可拷贝的函数对象（`std::function` 对函数对象做类型擦除并持有拷贝），而非 `std::function` 成员引用，避免悬空引用问题。

**4. 测试与运行**

沿用实验三（一）的测试用例（基础、加速、倒车），构建后 3 个测试程序全部通过，验证函数式实现与面向对象实现行为完全一致。

## 十、总结及心得体会

1. 函数对象本质上仍是对象，但把行为封装在 `operator()` 中，使"指令"可以直接像函数一样调用，代码更简洁直观。
2. `std::function` 通过类型擦除把不同的函数对象统一到同一类型，配合 `unordered_map` 形成非常紧凑的表驱动结构。
3. 深刻理解了生命周期问题：若表中存储对临时函数对象的引用，会形成悬空引用；存储 `std::function`（持有拷贝）则可安全使用。
4. 对比面向对象与函数式两种实现，体会到"同一问题可用多种范式解决"，选择取决于可扩展性、可读性与团队习惯。

## 十一、对本实验过程及方法、手段的改进建议

1. 各函数对象中 `fast`/`reverse` 的判断逻辑仍有重复，可用高阶函数或动作列表进一步抽象。
2. 指令表目前是 `Execute` 内的局部 `const` 对象，若希望复用，可提升为静态/单例对象。
3. 函数对象目前只操作 `PoseHandler` 状态，若需要更复杂的指令编排（如返回动作序列），可让 `operator()` 返回动作组，交由统一执行器执行。
