## 二、实验项目名称

面向对象编程 —— 用封装、继承与多态重构 Executor 组件并新增加速指令 F

## 三、实验目的

1. 掌握面向对象编程三大特性：封装、继承、多态。
2. 学会将面向过程的 `if/else` 实现逐步重构为面向对象结构。
3. 理解接口抽象：定义虚基类 `ICommand`，通过 `DoOperate` 统一分发指令。
4. 理解"对扩展开放、对修改关闭"（开闭原则）：新增指令时只需新增一个类，无需修改分发逻辑。
5. 在实验一基础上新增加速指令 `F`，体会状态管理（加速状态切换）与指令语义的组合。

## 四、实验内容

在实验一 `Executor` 基础上，使用面向对象编程的封装、继承与多态重构代码，并新增加速指令 `F`（对应需求文档《需求2-支持加速功能》）：

- 基础指令与实验一一致：`M` 前进 1 格、`L` 左转 90 度、`R` 右转 90 度。
- 新增加速指令 `F`：接收到后进入加速状态，再次收到 `F` 时取消（状态翻转）。
- 加速状态下：`M` 前进 2 格（不能跳跃，一格一格前进）；`L` 先前进 1 格再左转 90 度；`R` 先前进 1 格再右转 90 度。

未传初始位置时默认为 `(0, 0, N)`。课件假设参数合法且坐标运算不超出 `int32` 范围。

## 六、实验步骤及操作

**1. 封装：抽取成员函数**

将实验一中分散的移动/转向逻辑抽取为 `ExecutorImpl` 的成员函数 `Move()`、`TurnLeft()`、`TurnRight()`，并新增 `Fast()` 与 `IsFast()` 管理加速状态：

```cpp
class ExecutorImpl final : public Executor {
    void Move() noexcept; void TurnLeft() noexcept;
    void TurnRight() noexcept; void Fast() noexcept;
    bool IsFast() const noexcept;
    Pose pose_; bool fast_{false};
};
```

**2. 接口抽象与多态**

定义虚基类 `ICommand`，抽象方法 `DoOperate(ExecutorImpl&)`；`MoveCommand`、`TurnLeftCommand`、`TurnRightCommand`、`FastCommand` 继承 `ICommand`，各自实现具体操作：

```cpp
class ICommand {
public:
    virtual ~ICommand() = default;
    virtual void DoOperate(ExecutorImpl& executor) const noexcept = 0;
};

class MoveCommand final : public ICommand {
public:
    void DoOperate(ExecutorImpl& executor) const noexcept override {
        if (executor.IsFast()) { executor.Move(); }
        executor.Move();   // 加速时前进 2 格，否则前进 1 格
    }
};
```

**3. 分发逻辑**

`Execute` 中把指令字符映射为 `ICommand` 指针并统一调用 `DoOperate`，消除对每个指令的 `if/else`：

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept {
    for (const char cmd : commands) {
        std::unique_ptr<ICommand> cmder;
        if (cmd == 'M') cmder = std::make_unique<MoveCommand>();
        else if (cmd == 'L') cmder = std::make_unique<TurnLeftCommand>();
        else if (cmd == 'R') cmder = std::make_unique<TurnRightCommand>();
        else if (cmd == 'F') cmder = std::make_unique<FastCommand>();
        if (cmder) cmder->DoOperate(*this);
    }
}
```

**4. 测试与运行**

新增 `ExecutorFastTest.cpp` 覆盖加速状态下的 `M/L/R` 与再次 `F` 取消状态；抽离 `tests/TestSupport.hpp` 提供轻量测试框架 `ExpectPose` / `Run`。构建后两个测试程序均通过。

## 十、总结及心得体会

1. 通过封装，把"做什么"（指令）与"怎么做"（具体操作）分离，`Execute` 的职责变得更加单一。
2. 通过 `ICommand` 接口 + 多态，新增指令只需新增一个继承 `ICommand` 的类，符合开闭原则，代码扩展性明显提升。
3. 体会了重构的节奏：每一步重构后都应保证既有测试仍然通过，再继续下一步，避免"一次改太多"带来的回归风险。
4. 意识到状态（如加速标志）应作为对象成员统一管理，指令类通过 `executor.IsFast()` 读取状态，保持了状态与行为的合理耦合。

## 十一、对本实验过程及方法、手段的改进建议

1. `Execute` 中仍用 `if/else if` 逐个判断指令字符并 `new` 对象，可进一步改为"字符到指令对象"的表驱动，减少分支。
2. 指令类目前直接依赖 `ExecutorImpl`，形成一定的耦合；可考虑将状态数据抽离为独立的状态处理类，让指令只依赖状态，解除循环依赖。
3. 加速状态只用一个 `bool` 表示，若后续出现更多状态（如倒车），可抽象为状态机或正交的状态标志组合。
